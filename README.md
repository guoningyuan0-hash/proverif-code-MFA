# ProVerif Models for LMFA-WSN and E-LMFA-WSN

Formal verification models developed using ProVerif and the applied π-calculus for the manuscript:

**“Security Analysis and Enhancement of the LMFA-WSN Authentication Protocol”**

These models reproduce the two-layer security analysis presented in the manuscript:

1. A **Dolev–Yao symbolic analysis** of the original LMFA-WSN protocol and the enhanced E-LMFA-WSN protocol, covering authentication, secrecy, final-message integrity, and user–sensor-node session-key agreement (queries Q1–Q9).
2. A **post-session sensor-node-capture analysis** that demonstrates the exposure of past session keys in the original protocol (query Q10) and verifies that the enhanced protocol protects completed session keys under the modeled capture scenario.

## Files

| File | Protocol | Sessions | Node capture? | Purpose |
|------|----------|----------|---------------|---------|
| `LMFA_original_DY_aligned.pv` | Original LMFA-WSN | Replicated (`!`) | No | Baseline Dolev–Yao model; the authentication, final-message-integrity, and session-key-consistency queries Q6–Q9 fail. |
| `E-LMFA_DY_aligned.pv` | E-LMFA-WSN | Replicated (`!`) | No | Enhanced Dolev–Yao model; the corresponding Q1–Q9 security properties are proved within the specified symbolic model. |
| `LMFA_forward_secrecy.pv` | Original LMFA-WSN | Single | Yes (`phase 1`) | Demonstrates Q10: past session secrets are exposed after post-session disclosure of the sensor node’s long-term secret. |
| `E-LMFA_forward.pv` | E-LMFA-WSN | Single | Yes (`phase 1`) | Verifies Q10: the completed session keys remain protected under the modeled post-session sensor-node-capture scenario. |

The two `*_DY_aligned.pv` files evaluate the same security properties and use the same query identifiers, enabling a consistent before-and-after comparison.

The two forward-security models use the following block:

```proverif
phase 1;
out(pub, XSGj)
```

This block models an adversary that captures a sensor node and obtains its long-term secret `XSGj` after the protocol session has completed.

## Modeling notes

- **Channel and attacker:** All protocol messages are transmitted over the public channel `pub` under the standard Dolev–Yao adversary model.

- **Elliptic-curve operations:** `ecmult` is an idealized elliptic-curve scalar multiplication function. The equation

  ```proverif
  ecmult(k, ecmult(l, P)) = ecmult(l, ecmult(k, P))
  ```

  symbolically captures the ECDH shared-value relation without modeling the elliptic-curve discrete-logarithm problem.

- **Hash and XOR:** `H` is modeled as a symbolic perfect hash function. The `xor` operator provides left and right cancellation, and `s2b` converts a scalar value into a bitstring.

- **Fuzzy extractor:** The fuzzy extractor is abstracted symbolically using `FE` for secret extraction of `ω` and `FEpub` for the public helper value `θ`. Concrete biometric error correction is outside the scope of the model.

- **Test secrets:** `SecretU` and `SecretS` are auxiliary test values protected using `senc` and `sdec`. They are not protocol messages. They allow the `attacker(...)` queries to determine whether the session keys generated by the user and sensor node are exposed.

- **Long-term private values:** The modeled long-term private values include `IDUi`, `PWUi`, `BIOUi`, `IDSj`, `a` (the GWN master secret), and `Ppr` (the GWN private key). The registration phase is treated as secure. These values are initialized as private and are not disclosed, except for `XSGj` in the explicit post-session sensor-node-capture model.

- **Reachability instrumentation:** The `Reach(...)` events and their corresponding `query event(Reach(...))` statements are debugging instruments and are disabled by default. They may be enabled to confirm protocol executability.

## What the enhancement changes

E-LMFA-WSN modifies only the login and authentication phase of the original protocol.

- The authentication tags bind the affected transcript fields using domain-separated values `tag1`, `tag2`, and `tag3`. In particular, the final GWN-to-user authentication value is computed over:

  ```proverif
  H((tag3, M2, M3, M12, RS, T2, T3, T4))
  ```

  This binding prevents the message-substitution and session-context inconsistencies identified by queries Q6–Q9.

- The session key incorporates the ephemeral ECDH shared value `ZUS`, computed as:

  ```proverif
  ecmult(N1, RS)
  ```

  by the user and

  ```proverif
  ecmult(N3, M1)
  ```

  by the sensor node.

  This replaces the long-term-derived value used by the original protocol and protects completed session keys under the modeled post-session disclosure of `XSGj` examined by query Q10.

## How to run

Install [ProVerif](https://proverif.inria.fr/) and run the following commands from the repository directory:

```bash
proverif LMFA_original_DY_aligned.pv
proverif E-LMFA_DY_aligned.pv
proverif LMFA_forward_secrecy.pv
proverif E-LMFA_forward.pv
```

For each query, ProVerif reports:

- `true` or `false` for `attacker(...)` secrecy queries; or
- `RESULT ... is true` or `RESULT ... is false` for correspondence queries, together with an attack trace when a modeled property is violated.

---

## Expected outcomes

- `LMFA_original_DY_aligned.pv`  
  Queries Q6–Q9 concerning authentication, final-message integrity, and user–sensor-node session-key consistency are false, indicating counterexamples within the specified model.

- `E-LMFA_DY_aligned.pv`  
  The Q1–Q9 secrecy and correspondence properties, including `UserKey ==> SensorKey`, are true within the specified symbolic model.

- `LMFA_forward_secrecy.pv`  
  The `SecretU` and `SecretS` secrecy queries are false after the `phase 1` disclosure of `XSGj`, demonstrating the modeled Q10 weakness.

- `E-LMFA_forward.pv`  
  The corresponding secrecy queries remain true after the modeled post-session disclosure of `XSGj`.
